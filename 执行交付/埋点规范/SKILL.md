## 背景（Context）

本 Skill 基于 **事件驱动数据采集**和**产品分析指标体系**方法。

### 这个方法解决什么问题

产品上线后没有数据支撑决策，要么是**没埋点**，要么是**埋点不规范**（埋了一堆却分析不了）。埋点规范是"数据驱动产品"的基础设施。

### 核心框架

- **来源**：Google Analytics 数据采集最佳实践 + Amplitude 产品分析体系
- **核心原则**：每个埋点都要回答"这个数据用来干什么"，无效埋点是噪声不是信号
- **与其他 Skill 的关系**：
  - 执行交付/PRD编写 输出功能需求 → 本 Skill 补充数据采集需求
  - 本 Skill 输出的埋点方案 → 执行交付/数据分析 依赖的数据基础

### 适用边界

✅ **适用**：新功能的数据采集规范；埋点方案补全
❌ **不适用**：BI 数据仓库设计（用数据工程专项）
❌ **不适用**：第三方埋点 SDK 接入（属于工程问题）

## 阶段二：事件设计（Event）

### 事件命名规范

```markdown
## 事件命名

### 命名规则
- 使用下划线命名法
- 格式：行为对象_行为类型
- 示例：`page_view`, `button_click`, `form_submit`

### 行为类型
| 类型 | 说明 | 示例 |
|------|------|------|
| view | 页面/模块曝光 | page_view |
| click | 点击行为 | button_click |
| submit | 提交行为 | form_submit |
| success | 成功行为 | pay_success |
| error | 错误行为 | pay_error |
```

### 事件清单

```markdown
## 事件清单

### 启动类
| 事件名 | 触发时机 | 说明 |
|--------|---------|------|
| app_launch | 启动App时 | 启动事件，含来源 |
| app_exit | 退出App时 | 退出事件，含使用时长 |

### 页面类
| 事件名 | 触发时机 | 说明 |
|--------|---------|------|
| page_view | 页面展示时 | 页面停留时长 |
| module_view | 模块曝光时 | 内容区曝光 |

### 行为类
| 事件名 | 触发时机 | 说明 |
|--------|---------|------|
| button_click | 按钮点击时 | 含按钮位置 |
| form_submit | 表单提交时 | 含表单类型和结果 |
```

## 触发检查与兜底策略

### 🔍 触发条件检查

**进入标准流程的条件：**
- ✅ 用户有产品功能或业务指标需求

**进入兜底模式（满足任一）：**
- 🚨 用户说"设计埋点"但没有具体功能描述
- 🚨 用户不清楚要采集什么业务指标

**不触发本 Skill：**
- ⛔ BI 数据仓库设计（用数据工程专项）

### 🆘 兜底策略

**兜底触发**：没有功能描述或业务指标需求。

```markdown
# [前置] 埋点规范 — 需要先确认这些

## 在设计埋点方案之前，请先确认：

### 必须确认
1. **涉及哪些功能或页面？**
2. **想采集什么业务指标？**（DAU/转化率/留存等）

### 建议确认
3. 现有产品有没有已有的埋点规范？（复用还是新建）
4. 数据分析平台是什么？（不同平台埋点方式略有差异）
```
## Skill 协同
