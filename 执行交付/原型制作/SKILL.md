## 背景（Context）

本 Skill 将 PRD/需求描述快速转化为**可交互的 HTML 原型**。

### 这个方法解决什么问题

PRD 写完了，开发还没开始，PM 和设计师需要**提前验证方案是否合理**。Axure/Figma 太重，HTML 原型轻量、快速、可分享，是产品评审前的最佳验证工具。

### 核心框架

- **来源**：IDEO 设计思维 + Lean UX 快速原型方法
- **核心原则**：原型要"能用"，不只是"能看"；交互细节决定原型价值
- **与其他 Skill 的关系**：
  - 执行交付/PRD编写 输出 PRD → 本 Skill 转化为可交互原型
  - 本 Skill 输出的原型 → 执行交付/评审委员会 进行评审

### 适用边界

✅ **适用**：PRD 评审前的方案验证；与设计师的快速对齐
❌ **不适用**：高保真设计稿（交给 UI 设计师）
❌ **不适用**：复杂交互动画（拖拽、Canvas 游戏等，需专业工具）

# pm-prototype-design：PRD 转可交互 HTML 原型

## 你的角色

你是一位前端原型师，帮你把 PRD 或需求描述转化为可交互的 HTML 原型。你的原则是：**原型要能用，不只是能看——交互细节决定原型价值**。


## 步骤一：提取页面结构

### 做什么

1. **识别所有页面**：从 PRD 或描述中提取所有涉及的页面/视图
2. **梳理路由关系**：每个页面的入口、出口、返回逻辑
3. **列出核心组件**：按钮、表单、卡片、列表、弹窗等

### 输出：页面结构清单

```markdown
## 页面结构清单

| # | 页面名称 | 路由/ID | 核心组件 | 入口来源 | 出口去向 |
|---|---------|---------|---------|---------|---------|
| 1 | 首页 | /home | 导航栏、Banner、功能入口 | - | 点击功能入口 |
| 2 | 详情页 | /detail | 详情卡片、操作按钮 | 首页点击 | 返回/分享 |
```

---

## 步骤二：设计交互逻辑

### 交互类型矩阵

| 类型 | 说明 | 实现方式 |
|------|------|---------|
| **页面跳转** | 点击按钮跳转新页面 | `window.location.href` 或 JS 路由 |
| **表单提交** | 填写表单后提交 | 原生表单 + JS 处理 |
| **状态切换** | 展开/收起、显示/隐藏 | CSS class 切换 |
| **弹窗** | 点击触发弹出层 | `showModal()` 或 CSS overlay |
| **Toast** | 操作反馈提示 | 定时 auto-hide |
| **Tab 切换** | 同一页内切换内容 | classList 切换 |

### 交互细节定义

```markdown
## 交互定义

| 元素 | 交互行为 | 反馈 | 边界处理 |
|------|---------|------|---------|
| 按钮 A | 点击 | 跳转到详情页 | 加载中显示 spinner |
| 输入框 | 获得焦点 | 下划线高亮 | 空值时禁用提交 |
| 删除按钮 | 点击 | 弹出确认弹窗 | 确认后删除并 Toast 提示 |
```

---

## 步骤三：编写 HTML

### 技术规范

- **单文件**：所有 HTML + CSS + JS 在一个 `.html` 文件中
- **无外部依赖**：不使用 CDN JS/CSS（避免加载失败），图标用 SVG 内联
- **响应式**：支持 375px ~ 1440px 宽度，用 `@media` 适配
- **语义化**：使用 `<header>`、`<nav>`、`<main>`、`<section>` 等语义标签
- **CSS 变量**：定义主色、主色hover、背景色、边框色、圆角、阴影

### CSS 变量规范

```css
:root {
  --color-primary: #1a73e8;
  --color-primary-hover: #1765cc;
  --color-success: #34a853;
  --color-warning: #fbbc04;
  --color-error: #ea4335;
  --color-bg: #f8f9fa;
  --color-card: #ffffff;
  --color-text: #202124;
  --color-text-secondary: #5f6368;
  --color-border: #dadce0;
  --border-radius: 8px;
  --shadow: 0 1px 3px rgba(0,0,0,0.12), 0 1px 2px rgba(0,0,0,0.08);
}
```

### 组件库

每个原型必须包含以下基础组件：

**按钮**
```html
<button class="btn btn-primary">主要按钮</button>
<button class="btn btn-outline">次要按钮</button>
<button class="btn btn-text">文字按钮</button>
```

**输入框**
```html
<div class="form-group">
  <label>标签</label>
  <input type="text" class="input" placeholder="请输入">
  <span class="error-msg">错误提示</span>
</div>
```

**卡片**
```html
<div class="card">
  <div class="card-title">标题</div>
  <div class="card-body">内容</div>
</div>
```

**列表项**
```html
<div class="list-item">
  <div class="list-item-left">图标</div>
  <div class="list-item-content">主标题<br><span class="sub">副标题</span></div>
  <div class="list-item-right">箭头</div>
</div>
```

**弹窗**
```html
<div class="modal" id="modalConfirm">
  <div class="modal-mask"></div>
  <div class="modal-content">
    <div class="modal-title">确认删除</div>
    <div class="modal-body">确定要删除吗？</div>
    <div class="modal-footer">
      <button class="btn btn-outline" onclick="closeModal()">取消</button>
      <button class="btn btn-primary">确定</button>
    </div>
  </div>
</div>
```

**Toast**
```html
<div class="toast" id="toast"></div>
```

## 步骤四：自检清单

| # | 检查项 | 标准 |
|---|--------|------|
| 1 | 所有按钮可点击 | 点击有视觉或交互反馈 |
| 2 | 所有链接可跳转 | 页面间可来回切换 |
| 3 | 表单可填写提交 | 有验证提示和提交反馈 |
| 4 | 弹窗可打开关闭 | 遮罩层点击可关闭 |
| 5 | Toast 可正常显示隐藏 | 操作后出现，3秒后自动消失 |
| 6 | 响应式适配 | 375px 和 1440px 下布局正常 |
| 7 | 无控制台报错 | 打开 F12 无 Error |
| 8 | 页面状态完整 | 空状态、加载状态、错误状态有定义 |

## 兜底策略

### PRD 描述太简略

如果用户只说"做个原型"而没有具体页面描述：

```markdown
## ⚠️ 需要更多信息

为了生成准确的原型，请提供以下信息（至少一项）：
1. 页面的核心功能是什么？
2. 页面有哪些关键元素？（表单字段、按钮、信息区块）
3. 有没有手绘草图或参考产品截图？
4. 目标用户是谁？（影响视觉风格）
```

### 涉及复杂交互

如果描述涉及复杂交互动画（拖拽、Canvas 游戏、实时协作）：
1. 降低原型保真度，保留核心交互
2. 在文档中注明"此处需高保真设计稿支撑"
3. 建议配合 UI 设计师完成

## 输出检查清单

| # | 检查项 | 标准 |
|---|--------|------|
| 1 | 页面覆盖完整 | 所有 PRD 涉及的页面都有原型 |
| 2 | 交互逻辑正确 | 所有跳转、弹窗、状态变化可演示 |
| 3 | 边界情况覆盖 | 空状态、加载态、错误态都有展示 |
| 4 | 与设计规范一致 | 组件、颜色、字体符合设计规范 |
| 5 | 标注清晰 | 有必要的交互标注和说明 |

## 触发检查与兜底策略

### 🔍 触发条件检查

**进入标准流程的条件：**
- ✅ 用户有 PRD 或详细的页面描述

**进入兜底模式（满足任一）：**
- 🚨 用户说"做个原型"但没有任何页面描述
- 🚨 涉及复杂交互（拖拽游戏、Canvas、实时协作）超出前端原型范畴

**不触发本 Skill：**
- ⛔ PRD 撰写（用 执行交付/PRD编写）
- ⛔ 高保真 UI 设计（用 Figma/Axure）

### 🆘 兜底策略

**兜底触发**：用户没有任何页面描述信息。

```markdown
# [前置] 原型设计 — 需要先确认这些

## 在生成原型之前，请先确认：

### 必须确认
1. 页面的核心功能是什么？（一句话描述）
2. 页面有哪些关键元素？（表单字段、按钮、信息区块）

### 建议确认
3. 有没有手绘草图或参考产品截图？
4. 目标用户是谁？（影响视觉风格）

---
如果涉及复杂交互，我会降低原型保真度，保留核心交互，
并在文档中注明"此处需高保真设计稿支撑"。
```
