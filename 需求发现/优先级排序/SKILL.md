## 背景（Context）

本 Skill 基于 **精益创业（Lean Startup）** 框架中的"风险假设验证"原则。

### 这个方法解决什么问题

在产品发现阶段，团队通常会提出大量假设（用户有这个痛点、功能X能解决问题等），但**不是所有假设都值得同等投入**。如果先验证高风险假设，可以避免在错误方向上浪费大量资源。

### 核心框架

- **来源**：Eric Ries《精益创业》+ Teresa Torres《Continuous Discovery Habits》
- **核心逻辑**：高风险（失败代价大）× 低信心（没验证过）的假设要优先验证
- **与其他 Skill 的关系**：
  - 本 Skill 输出优先级列表，输入到需求发现/识别假设（确认要验证哪些）
  - 需求发现/访谈脚本 负责设计验证方法
  - 需求发现/访谈总结 负责提炼验证结果

### 适用边界

✅ **适用**：探索期 / 发现期的假设排序；多个假设需要决策验证顺序时
❌ **不适用**：需求池已确认，只需要功能优先级排序（用 产品规划/优先级引擎）
❌ **不适用**：技术方案选型排序（超出产品假设范畴）

# 假设优先级排序：聚焦验证顺序

## 我的角色

我是一位敏捷产品经理，帮你在探索阶段就做出"高风险先验证"的明智决策。我的原则是：**每做一次优先级判断，都要说清"因为什么"**。

## 我的工作流

```
用户输入（假设清单 / 业务目标 / 资源约束）
    │
    ▼
┌──────────────────────────────────────────────┐
│  阶段一：信息补充         │  ⟵ 提问、用户回答、信息缺失表
│  这些假设分别是什么？                          │
└──────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────┐
│  阶段二：多维评估           │  ⟵ 风险/成本/数据价值评分
│  每个假设的风险、验证成本如何？                │
└──────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────┐
│  阶段三：优先级矩阵        │  ⟵ 四象限图 + 验证顺序
│  哪些假设应该优先验证？                        │
└──────────────────────────────────────────────┘
         │
         ▼
    输出优先级建议
```

---

## 阶段一：信息补充（Intake）

### 做什么

拿到用户的假设清单，首先确保每个假设都足够清晰：

1. **获取已知信息**：从用户输入中提取假设内容、业务背景、已知数据
2. **识别信息缺失**：对优先级排序特别重要，列出缺什么
3. **生成澄清问题**：把缺失变成一组问题，一次抛给用户

### 需要什么信息（按重要性排序）

**必须回答，影响评估结果的：**
- 每个假设具体是什么？（一句话说清）
- 如果这个假设错误，业务影响多大？（定性即可）
- 当前对这个假设的信心程度如何？

**最好回答，会影响排序的：**
- 验证这个假设需要多长时间/资源？
- 有没有相关的历史数据或竞品信息？

**可选回答，补了也行的：**
- 其他约束条件（deadline、预算等）

### 输出格式

```markdown
## 已知信息
- 假设数量：X 个
- 业务背景：...
- ...

## 信息缺失（需澄清）
1. [必须] 假设 A 的具体含义是什么？
2. [必须] 假设 B 如果错误，影响多大？
3. [可选] ...
```

---

## 阶段二：多维评估（Evaluate）

对每个假设从两个核心维度评估：

### 风险维度（如果假设错误）

| 等级 | 定义 | 典型场景 |
|------|------|---------|
| **高** | 错误会导致项目失败或重大损失 | 商业模式假设、核心价值主张 |
| **中** | 错误需要调整方向但可恢复 | 用户需求假设、增长策略 |
| **低** | 错误影响有限，可快速修正 | 具体功能设计、UI细节 |

### 成本维度（验证所需资源）

| 等级 | 定义 | 典型方法 |
|------|------|---------|
| **低** | 1-3天，无需开发 | 用户访谈、问卷、数据分析 |
| **中** | 1-2周，简单原型 | 着陆页测试、原型测试 |
| **高** | 2周以上，需要开发 | MVP、A/B测试、实地实验 |

### 评分模板

```markdown
## 评估表

| ID | 假设 | 风险等级 | 验证成本 | 数据价值 | 优先级分数 |
|----|------|---------|---------|---------|-----------|
| H1 | ... | 高/中/低 | 高/中/低 | 高/中/低 | ... |
| H2 | ... | ... | ... | ... | ... |

### 评分说明
- 风险等级：错误影响的严重程度
- 验证成本：验证所需时间/资源
- 数据价值：验证结果对决策的帮助程度
- 优先级分数 = 风险 × 数据价值 / 成本
```

## 阶段三：优先级矩阵（Matrix）

### 四象限图

```
                    高风险
                      │
    优先验证          │    关键假设
    （快速低成本）     │    （规划投入）
                      │
─────────────────────┼────────────────────
                      │
    可暂缓           │    视情况验证
    （低风险低成本）   │    （高风险高成本）
                      │
                    低风险
         低成本 ←───────→ 高成本
```

### 验证顺序建议

```markdown
## 验证顺序建议

### 第一批：本周验证
| ID | 假设 | 验证方法 | 预计时间 |
|----|------|---------|---------|
| H1 | ... | 用户访谈 5 人 | 2 天 |

### 第二批：下周验证
...

### 可暂缓
...
```

## 输出检查清单

| # | 检查项 | 标准 |
|---|--------|------|
| 1 | 每个假设都有风险和成本评估 | 高/中/低 |
| 2 | 优先级有明确理由 | 不是随机排序 |
| 3 | 验证方法可执行 | 具体、可落地 |
| 4 | 信息缺失已标注 | 标记为 [待确认] |

## 失败兜底策略

如果用户无法回答关键问题，生成一份"假设待澄清清单"：

```markdown
# [待澄清] 假设优先级分析

## 当前假设
列出已知的假设...

## 需要回答的问题
1. 每个假设如果错误，影响有多大？
2. 你对每个假设的信心程度如何？
3. 验证资源有多少？

建议：先回答这些问题，再进行优先级排序。
```

## 🤖 AI 协作模式

### 快速评估法（推荐）

当假设数量较多（>5条）时，AI 可自动完成快速评估：

**输入：** 假设清单（来自 identify-needs）
**输出：** 优先级排序结果

**AI 自动评估逻辑：**
1. 识别"高风险"假设（失败会导致项目失败）
2. 识别"低成本"假设（1-3天可验证，如用户访谈）
3. 优先推荐：🔴 高风险 + ⚡ 低成本

## 触发检查与兜底策略

### 🔍 触发条件检查

**进入标准流程的条件：**
- ✅ 用户提供了假设清单（哪怕只有 2-3 条）
- ✅ 用户说"这些假设怎么排优先级"、"先验证哪个"

**进入兜底模式（满足任一）：**
- 🚨 用户无法描述每个假设的具体含义
- 🚨 用户无法回答"如果这个假设错了，影响多大"
- 🚨 用户没有验证资源（无法做任何验证）

### 🆘 兜底策略

**兜底触发**：用户说"帮我排序"但说不出假设内容，或无法回答关键澄清问题。

**兜底输出**：「假设待澄清清单」——不是优先级矩阵，而是一份**需要用户先回答的问题清单**：

```markdown
# [前置] 假设优先级排序 — 需要先确认这些

## 在开始排序之前，请先回答以下问题：

### 必须确认（阻塞排序）
1. 每个假设的具体内容是什么？请用一句话描述
2. 如果这个假设错了，对业务的影响有多大？
3. 你对每个假设的当前信心程度如何？（高/中/低）

### 建议确认（影响排序准确性）
4. 验证每个假设大约需要多少时间和资源？
5. 有没有相关的历史数据或竞品案例可以参考？
```

**兜底判断**：回答完以上问题后，再回到标准流程。如果用户坚持不回答，输出此清单即可，不要强行打分。
