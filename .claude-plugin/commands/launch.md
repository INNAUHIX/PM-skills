# /launch — 发布全流程

从已确认交付范围出发，开发交接 → 制定发布计划 → 执行发布 → 上线复盘。

## 前置条件

- PRD 已评审通过，或至少交付范围已明确
- 核心负责人已确定
- 发布对象不是“纯概念需求”

## 运行模式

- `full`：完整交接、发布、回滚、复盘
- `lite`：低风险发布，只输出最小发布包

### 模式选择建议

| 当前场景 | 推荐模式 | 原因 |
|---------|---------|------|
| 重大版本/高风险功能 | `full` | 需要完整灰度和回滚策略 |
| 小功能、无库表变更、有开关 | `lite` | 只保留关键检查和回滚 |
| 企业客户分批开通 | `full` | 需要灰度名单和培训准备 |

## 跳步规则

- 如果已有工程交接包，可直接进入 `release-launch`
- 如果已有发布计划，只补回滚和复盘模板
- 如果用户只有模糊需求，不建议直接进入 `/launch`，应先去 `/write-prd`

## 使用场景

当你准备发布一个版本或功能时使用：
- `制定发布计划`
- `准备上线 XX 功能`
- `发版流程怎么走`
- `这个功能已经开发好了，帮我准备发布`
- `我们已经有 PRD 和交接包，直接出发布方案`

## Skill 链路

1. **engineering-handoff** — 输出工程交接包、依赖清单和验收口径
2. **release-launch** — 制定灰度发布策略、发布检查清单和回滚方案
3. **retrospective-review** — 上线后复盘并生成行动项

```markdown

## 核心交付物
- 工程交接包：
- 发布计划：
- 回滚手册：
- 复盘模板：

## 建议下一步
- 发布前还缺什么：
- 发布后重点盯什么：
- 当前状态：`ready-to-launch / launched / reviewed`
```

## 状态机位置

- 进入前通常处于 `ready-to-build`
- 发布准备完成后进入 `ready-to-launch`
- 发布完成进入 `launched`
- 复盘完成进入 `reviewed`

## 示例

```
/launch v2.5.0
/launch 会员体系新功能
/launch XX 功能灰度发布
/launch 用户分享功能，已完成开发和测试
/launch lite 草稿自动保存功能
```

## 输出

- 上线计划（含依赖清单）
- 灰度策略 + 发布检查清单
- 回滚操作手册
- 上线复盘报告 + 行动项
- 建议下一步命令
