# /discover — 需求发现流

从模糊想法出发，识别假设 → 优先级排序 → 设计访谈 → 提炼洞察 → 生成新假设

## 使用场景

当你有产品想法但不知从何入手时：
- "想做一个 XX 产品"
- "帮我分析一个 XX 市场"
- "用户有这个需求，怎么验证"
- "我只想先整理假设"
- "我还没有访谈记录，只想先出访谈提纲"

## Skill 链路

1. **识别假设** — 将模糊想法转化为结构化假设
2. **优先级排序** — 对假设按风险/验证成本优先级排序
3. **访谈脚本** — 针对高优先级假设设计访谈问题
4. **访谈总结** — 从访谈记录提炼洞察和新的假设

## 阶段规则

- 如果用户没有访谈记录，不进入 `访谈总结`
- 如果用户已提供假设清单，跳过 `识别假设`
- 如果用户已完成优先级排序，跳过 `优先级排序`

## 状态位置

- 进入前通常处于 `idea`
- 完成假设验证优先级后进入 `validated`
- 如果只完成访谈提纲但未验证，仍停在 `idea`

## 示例

```
/discover 做一个 AI 写作助手，帮助用户提高内容产出效率
/discover 我们想进入 B2B 项目管理市场
/discover 验证用户是否愿意为 XX 功能付费
/discover ideation 做一个用户分组功能
/discover interview-prep 验证用户是否愿意主动分享内容
```

## 输出

- 假设清单（含验证等级）
- 优先级排序结果
- 访谈提纲（针对高优先级假设）
- 洞察清单 + 待验证假设
- 建议下一步行动
