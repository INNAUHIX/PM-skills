## 背景（Context）

本 Skill 基于 **Value Proposition Canvas（价值主张画布）** 和 **JTBD 框架**。

### 这个方法解决什么问题

产品团队经常**把功能当价值主张**——"我们有 AI 写作功能"不是价值主张，"让用户每天多节省 30 分钟写作时间"才是。价值主张不清，导致营销无力、销售说不清、用户记不住。

### 核心框架

- **来源**：Alexander Osterwalder《Value Proposition Design》+ Tony Ulwick《What Customers Want》
- **关键原则**：价值主张必须回答"用户为什么选我们而不选竞品/现状"
- **与其他 Skill 的关系**：
  - 产品规划/竞品分析 输出差异化方向 → 本 Skill 据此提炼差异化主张
  - 需求发现/识别假设 输出核心假设 → 本 Skill 验证价值主张是否对用户真正重要

### 适用边界

✅ **适用**：新产品定位；已有产品的核心信息更新；融资 BP / 官网文案
❌ **不适用**：完整的商业计划书（用专项 BP 工具）
❌ **不适用**：品牌战略（超出产品价值主张范畴）

# 价值主张设计：从用户需求到产品卖点

## 我的角色

我是一位产品营销专家，帮你把模糊的产品想法转化为清晰、可落地、有说服力的价值主张。我的原则是：**每一个卖点都要能回答"用户为什么要在乎"，每一个主张都要能经得起竞品的挑战**。

## 步骤一：用户洞察

### 核心问题框架

回答三个基本问题：

```markdown
### 用户洞察三问

1. **他们是谁？**（人口属性 + 行为特征）
   - 职业/角色：[如：电商店主、HR、销售]
   - 使用场景：[如：每天处理订单、管理客服]
   - 决策模式：[个人决策 / 团队决策 / 审批制]

2. **他们最大的痛苦是什么？**（Jobs-to-be-done）
   - 功能性工作：[他们想完成什么任务？]
     例：管理 200+ SKU 的库存
   - 情感性工作：[他们希望有什么感受？]
     例：不用担心库存出错，能安心睡觉
   - 社会性工作：[他们希望别人怎么看他们？]
     例：让客户觉得我们很专业

3. **他们现在怎么解决？**（现状地图）
   - 当前方案：[用 Excel / 雇人 / 手工流程]
   - 痛点评分：[1-10，这个痛点有多痛？]
   - 切换意愿：[1-10，愿意换新方案的意愿有多强？]
```

### 痛苦程度评分

| 评分 | 程度 | 说明 | 价值主张机会 |
|------|------|------|------------|
| 1-3 | 轻微 | 有点烦，但不致命 | 很难卖 |
| 4-6 | 中度 | 影响效率，愿意尝试 | 需要明显优势才换 |
| 7-8 | 强烈 | 严重影响业务，愿意付费 | 核心机会 |
| 9-10 | 生死攸关 | 不解决就没了 | 卖什么都不难 |

## 步骤二：价值匹配（Value Proposition Canvas）

### 价值主张画布（VPC）

把用户痛点与产品价值一一对应，不留空白：

```markdown
### 价值主张画布

**用户画像：[给这个用户群起个名字，如"效率优先型店长"]**

#### 用户的痛苦（Pains）
| # | 痛点 | 痛苦程度 | 现有解决方案 | 对应我们的功能 |
|---|------|---------|------------|------------|
| P1 | 库存数据不准确，每周盘点都要加班 | 8 | Excel 表格 | 智能库存同步 |
| P2 | 多平台订单要手动同步，容易漏单 | 9 | 手工复制粘贴 | 订单自动归集 |
| P3 | 员工不会用系统，培训成本高 | 6 | 录操作视频 | 引导式交互设计 |

#### 用户的收益（Gains）
| # | 期望收益 | 重要程度 | 对应我们的功能 |
|---|---------|---------|------------|
| G1 | 数据完全准确，不用反复核对 | 高 | 实时同步 + 自动校验 |
| G2 | 下班前就能完成当天盘点 | 高 | 移动端扫码盘点 |
| G3 | 系统上手快，新人不用培训 | 中 | 引导 + 模板化 |

#### 产品价值（Value Proposition）
| 对应痛点 | 我们的解决方案 | 价值类型 |
|---------|-------------|---------|
| P1 + P2 | 多平台自动同步 + 实时库存 | 止痛（消除痛苦）|
| G1 | 数据自动校验 + 异常预警 | 增益（创造收益）|
| P3 | 引导式交互 + 7×24 客服 | 情感（降低门槛）|

### 检查：价值主张画布完整性

- [ ] 核心痛点（P1）有对应功能
- [ ] 核心收益（G1）有支撑数据
- [ ] 没有功能没有对应痛点（避免自嗨）
- [ ] 没有痛点没有对应功能（避免遗漏）
```

## 步骤三：价值主张提炼

### 一句话价值主张模板

**结构：**
> [产品名] 帮助 [目标用户] 解决 [核心问题]，通过 [核心方法]，让用户能够 [实现什么价值]。

**示例：**
> 小店管家帮助"日均 50+ 单的中小电商卖家"解决"多平台订单管理混乱"的问题，通过"自动归集 + 智能分单"技术，让他们能够"用一个后台处理所有订单，不再漏单、不错单"。

### 价值主张三要素检查

| 要素 | 定义 | 检查问题 | 通过标准 |
|------|------|---------|---------|
| **清晰** | 用户能听懂 | "不用解释第二遍" | 普通人 5 秒复述 |
| **可信** | 用户会相信 | "他们真的做到了吗" | 有数据/案例/背书 |
| **差异化** | 竞品做不到 | "为什么选你不选别人" | 有明确差异化理由 |

### 差异化定位陈述

```markdown
## 差异化定位陈述

对于 [目标用户]，
他们当前用 [竞品/现状] 来 [完成某任务]，
但 [存在什么痛点/不满]，
我们的产品 [提供什么能力]，
让用户能够 [获得什么结果]，
与 [竞品A/竞品B] 相比，我们 [关键差异点]。

---

示例：
对于"日均 50+ 单的中小电商卖家"，
他们当前用"多平台后台 + Excel"来管理订单，
但经常因平台规则不同导致漏单错单，
我们的产品提供"AI 订单归集 + 自动分单"能力，
让他们能够"一个后台管所有平台，日均节省 2 小时"，
与"超级马助手"相比，我们是"专门为中小卖家设计的多平台聚合工具，而非大卖家定制系统"。
```

## 步骤四：信息矩阵

不同场景说不同的话，但核心主张不变：

```markdown
## 信息矩阵

| 场景 | 核心信息 | 说话风格 | 支撑材料 |
|------|---------|---------|---------|
| 产品官网首页 | 一句话价值主张 | 直接、有力 | 用户数据 + 案例 |
| 产品详情页 | 3 大卖点 + 支撑证据 | 详细、可信 | 对比数据 + 截图 |
| 销售话术 | 痛点共鸣 → 方案 → 效果 | 引导式 | 案例故事 |
| 融资 BP | 市场规模 + 差异化 + 数据 | 专业、简洁 | 图表 + 第三方背书 |
| 朋友圈广告 | 一句话痛点 + 方案 | 情绪化、场景化 | 视觉冲击 |
```

### 卖点结构（详情页用）

每个卖点的标准结构：
1. **标题**（一句话，不要超过 12 个字）
2. **痛点**（用户现在的痛苦，1 句话）
3. **方案**（我们怎么解决，1 句话）
4. **证据**（数据/案例/对比，1-2 条）
5. **行动引导**（让用户下一步做什么）

```markdown
## 卖点模板示例

### 卖点一：多平台订单聚合

**标题：**[再也不用切换后台了]

**痛点：**
日均 100 单，要同时管 5 个平台，每个平台规则不同，一不小心就漏单。

**方案：**
小店管家自动抓取全平台订单，智能归集到同一个后台，支持一键批量处理。

**证据：**
- 🏆 已服务 50,000+ 电商卖家，平均日节省 2.3 小时
- 平均错漏率从 3.2% 降至 0.1%（来自 2024 年用户调研）
- "用了 3 个月，再没漏过一单"——某天猫卖家

**行动：**
免费试用 30 天，看得见效果再付费 →
```

## 步骤五：验证与迭代

### 自我质疑清单

在定稿之前，用这些问题挑战自己：

```markdown
## 价值主张自检

### 🔴 致命问题（有一个就别用）
- [ ] 用户能在 5 秒内复述这个价值主张吗？
- [ ] 这个主张竞品也能说吗？（如果能，就不是差异化）
- [ ] 我们真的有数据/案例支撑这个主张吗？

### 🟡 重要问题（尽量解决）
- [ ] 这个主张能说服新用户而不是老用户吗？
- [ ] 价格敏感用户和非价格敏感用户都能被说服吗？
- [ ] 这个主张能持续 1-2 年不过时吗？

### 🟢 优化问题（锦上添花）
- [ ] 有情绪共鸣吗？（不只是理性诉求）
- [ ] 朗朗上口吗？（方便口碑传播）
```

## 兜底策略

### 用户无法描述产品

如果用户说"帮我写价值主张"但没有提供任何产品信息：
1. 先用问题清单补信息（目标用户、核心功能、竞品、用户痛点）
2. 如果信息仍然不足，输出「价值主张设计问卷」，引导用户填写关键信息
3. 一旦有基础信息，立即开始

## 触发检查与兜条策略

### 🔍 触发条件检查

**进入标准流程的条件：**
- ✅ 用户有产品描述（或核心功能描述）
- ✅ 知道目标用户是谁

**进入兜底模式（满足任一）：**
- 🚨 用户说"帮我写价值主张"但没有任何产品描述
- 🚨 用户只说了功能列表，没有用户痛点和差异化方向
- 🚨 用户想对比多个产品定位（用「competitive-strategy」先分析竞争格局）

**不触发本 Skill：**
- ⛔ 完整的商业计划书（用专项 BP 工具）
- ⛔ 竞品对比分析（先做「competitive-strategy」）

### 🆘 兜底策略

**兜底触发**：没有产品描述或用户痛点信息。

```markdown
# [前置] 价值主张设计 — 需要先确认这些

## 在生成价值主张之前，请先回答：

### 必须确认
1. **产品是什么？** 核心功能是什么？（一句话描述）
2. **目标用户是谁？** 哪类用户会使用？
3. **用户最大的痛点是什么？** 他们现在怎么解决这个问题？

### 建议确认
4. 主要竞品是谁？用户为什么选竞品？
5. 我们的产品与竞品相比，最大的差异是什么？

---
如果信息严重不足，我会先输出「价值主张设计问卷」，
引导用户补全核心信息，再生成价值主张。
```
